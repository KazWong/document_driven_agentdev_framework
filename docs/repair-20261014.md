### Rejected hypothesis, retained transparently

The first fault-injection batch reported 22 failures, but one proposed test incorrectly demanded that Final Acceptance repeat every mandatory targeted verification. The normative final-acceptance design deliberately selects a smaller suite from existing VER obligations. That proposed restriction was withdrawn and replaced with a positive subset-contract regression. Therefore that batch represents 21 valid reproduced failing cases, **not 22 confirmed defects**. Boundary tests reproduced 12 failures; stage/restart tests reproduced 10 failures plus one already-passing negative guard. Case counts are not counts of independent root causes.

An early suspicion that Coder output could write root `.git` metadata was not substantiated: the existing scope policy already denies those paths. No such vulnerability is claimed as fixed. The confirmed path defects concern Docker mount components and literal Git pathspec handling.
